\begin{abstract}
FPGA accelerator papers often report performance from models or simulation,
leaving the gap to real hardware unquantified. We present an INT8 CNN
accelerator for the AMD Kria KV260 whose performance is exactly predictable.
An $8{\times}8$ output-stationary array of DSP48E2 slices runs LeNet-5 and a
CIFAR-10 network entirely on chip at 250\,MHz, using 80 DSPs and 16.5k LUTs.
Its requantization is verified bit-exact against the floating-point
reference on every non-saturating input. An analytical cycle model, fixed
before RTL simulation, predicts every layer's cycle count with zero error on
20,000 test images and 286 random layer jobs, in RTL simulation and on the
board. Measured on the KV260, compute takes 65.7\,$\mu$s (LeNet-5) and
417.0\,$\mu$s (CIFAR-10) with one cycle count over 3.65M inferences. End to
end, the accelerator is 2.1--3.1$\times$ faster than the best on-board CPU
baseline and 1.5$\times$ faster than the AMD DPU on LeNet-5, but 1.6$\times$
slower on CIFAR-10.
\end{abstract}

\section{Introduction}\label{sec:intro}
FPGA CNN accelerators are usually evaluated with an analytical model or a
simulator, and the design that reaches the board is then characterized by a
few throughput figures. We are not aware of work that reports, layer by
layer, how far such a model is from the hardware. That gap matters:
embedded and real-time systems need latency they can budget for, and a
performance model is only useful for design-space exploration if it can be
trusted without building every design.

We take the opposite route. We wrote the cycle model first, derived its two
constants from the RTL's stage latencies and committed them before the first
simulation of the core, and then held the RTL and the board to that model
cycle for cycle. The design is deliberately small, and our claim is
exactness, not peak throughput. Our contributions are:
\begin{itemize}
\item an $8{\times}8$ output-stationary INT8 accelerator on the KV260 whose
requantization is verified bit-exact on every non-saturating input;
\item a closed-form cycle model, fixed before RTL simulation, that predicts
every layer's cycles exactly in RTL simulation and on the board;
\item a board evaluation of compute and end-to-end latency, SOM-rail energy and a
clock sweep, against the on-board CPU and the AMD DPU; and
\item a reproducible artifact in which every number is generated by script
from a tagged commit.
\end{itemize}
