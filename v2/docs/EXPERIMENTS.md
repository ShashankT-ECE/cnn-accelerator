# V2 Experiment Plan

## Thesis
A small INT8 output-stationary accelerator with bit-exact end-to-end inference and cycle-exact agreement between the analytical model, RTL simulation, and measured KV260 execution.

## A — Core results
- **A1 Correctness:** full 10k test sets, both nets. Record images tested, output mismatches vs golden (target 0), golden accuracy, hardware accuracy.
- **A2 Latency:** per-layer and total PL cycles; µs at the pl_clk0 **PLL read-back** clock, the clock of record (DECISIONS D20; the measured f_meas is a cross-check only, see "Measured PL clock"); wall-clock per image as median with the distribution-free 95 % CI and p95 after a 50-image warm-up discard.
- **A3 Three-way cycle agreement per layer:** model_cycles, rtl_cycles, hw_cycles, rtl_err_pct, hw_err_pct.
- **A3b Per-layer cycle determinism:** every test image of both nets (10,000 per net) on the board (`exp_layer_spread.py`, step `s2.layerspread`, reusing the A2/A3 per-image counters `hw_cycles_<net>.npz` when they cover every image at the same source and clock): per layer and total, min / max / number of distinct values / spread (max − min) of LAYER_CYC and TOTAL_CYC over all images; expected spread 0 (data-independent schedule). RTL reference = the committed full-test-set RTL simulation `results/rtl_full10k.csv` (cycle-exact on all images). Output `hw_layer_spread.csv`.
- **A3-general Random-shape jobs** (board side `board/exp_shapes.py`, step `s2.shapes`, group "shapes"; set and RTL side: `v2/shapes/`, other owner): the seeded random multi-layer shape set (`v2/build/shapes/<seed>/`, ~300 jobs in categories incl. refuse jobs; golden outputs, byte masks and cycles from the model) shipped in the data package (`data/shapes/`, SHIP.json SHA256-chained to PACKAGE.json / DEPLOY_INFO) and run on the board job by job: every memory image and descriptor written and read back, start, STATUS poll, counters, output ACT words (bit-exact under the byte mask) or LOGIT (out_raw); refuse jobs: ERR_CODE and TOTAL_CYC = C_START. Three-way cycle agreement per job (per layer + total + MAC_ACTIVE): model / RTL sim (`results/shapes_rtl.csv` row of the same job, only for the same `shapeset_sha256`) / accelerator. **Hard 15 min cap** (`--budget-s` ≤ 900 s inside the script; stops cleanly after the current job, `capped`, `jobs_completed / jobs_total` recorded); job order = seeded shuffle within each category, round-robin over categories, so a capped run still covers every category. Output `hw_shapes.csv`: one row per job + a summary row (jobs, outputs exact, refuse OK, cycles == model, cycles == RTL / compared, max |err|, categories covered), label "A3-general random shapes, measured on KV260".
- **A4 Utilization per layer:** MAC_ACTIVE/TOTAL, compared with the theoretical value.
- **A5 Same-board CPU baseline (Cortex-A53):** INT8 numpy and FP32. Protocol: warm-up discarded, median of ≥100 runs with the distribution-free 95 % CI, 1 thread and 4 threads reported separately (1-thread workers pinned to the measurement core, 4-thread workers to cores 0-3; affinity read back and recorded), numpy/BLAS version recorded. A DPU baseline (`v2/dpu/dpu_session.py`, other owner) is scheduled in the same "baselines" group only if that script is deployed. Split compute-only vs end-to-end on both CPU and FPGA (FPGA compute-only = PL counter; FPGA end-to-end = input write + start + poll + logit read).
- **A6 Implementation:** LUT/FF/DSP/BRAM, WNS, achieved clock.

## B — Power and system
- **B1 SOM-rail power (INA260):** primary measurement = the on-board INA260 on the SOM rail (VCC_SOM), sampled remotely on the board by `board/power_log.py` (hwmon `ina260*` node, else `platformstats -p`, else read-only I2C; backend, device and sensor update/averaging limits recorded) at a fixed requested rate (default 10 Hz); the achieved rate (samples / elapsed) and the max inter-sample gap are recorded.
  - **Protocol** (per net): per repeat the three run phases accelerator loop / **control** / CPU baseline (60 s each), each bracketed by idle phases (60 s), repeated 3×, plus one final idle 60 s = 19 phases ≈ 19 min per net (each phase with START/STOP banners; `--no-control` gives the earlier 13-phase protocol). The order of the run phases is a **seeded random permutation per repeat** (`power_log.py --order random --order-seed S`, recorded as `phase_order` / `order_seed` in every phase and summary row) so that a slow drift of the rail does not always hit the same kind; with `--order fixed` the order is idle → accel → idle → control → idle → CPU. Accelerator loop per image: `GosDevice.infer` (input write, pre-start clear, start, STATUS poll, LOGIT read; host path recorded), TOTAL_CYC read, PS dequant + argmax. **Control** = the same host loop with the accelerator **not started**: input write, the soft_reset + clear poll, a STATUS poll spin for the median start→done time of the preceding accelerator phase, LOGIT read, TOTAL_CYC read, PS dequant; STATUS ≠ 0 or TOTAL_CYC ≠ 0 aborts the step. ΔP_accel − ΔP_control therefore isolates what the PL compute adds on top of the host-loop activity (PS, DDR, AXI polling). CPU baseline = `cpu_int8_ref`, 1 thread.
  - **Report** per phase mean, std, n samples, rate, duration, images; per repeat and mean/std over the 3 repeats: P_idle (mean of the two idle phases bracketing the run phase), P_accel, P_control, P_cpu, ΔP = P_run − P_idle, time per image = phase duration / images, energy per image = ΔP × time per image; accelerator energy two ways: **E_sys** = ΔP_accel × wall time per image (host loop included) and **E_comp** = ΔP_accel × TOTAL_CYC / f (TOTAL_CYC = hardware counter, median over the phase's images; f = the measured f_meas at that clock, else the pl_clk0 read back; `f_used_mhz` / `f_used_source` recorded); **duty cycle** = (TOTAL_CYC / f) / wall time per image; the control-subtracted variants ΔP_accel − ΔP_control, E_sys,net and E_comp,net — all computed by the script (`power_log.summarize`), never typed; paper table B1 shows them with placeholders until board data.
  - **Label** every number "SOM-rail power (INA260)": it is SOM-rail power, not accelerator-only power and not board input power. The INA260 is the **only** power measurement of the board sessions (decision 2026-09-29: no external meter).
  - **Rail coverage** (board/README.md "VCC_SOM coverage (INA260)" has the verbatim quotes): UG1089 v1.3 (May 14, 2024), Ch. 2 "Powering the Starter Kit and Power Budgets": "The SOM power rail (VCC_SOM) is powered by the 5V supply" and "A power monitor device is available on the SOM power rail (VCC_SOM). You can access the total power consumed by the SOM module through the I2C bus"; "The carrier card provides the programmable logic (PL) the VCCO voltage rails". DS987 v1.0 (Apr 20, 2021): "SOC power supplies derived from a single +5V input", "PL I/O supplies customized through carrier card defined power rails", PS/PL VCCO rails "supplied by the carrier card". The upstream KV260 carrier device tree names `ina260@40` "ina260-u14" on the carrier I2C bus. So VCC_SOM = the SOM's +5 V input: everything on the SOM (PS incl. the Python host and the CPU baseline, PL core, and — inferred, not stated per rail — the on-SOM DDR4, flash and regulator losses), excluding the carrier-supplied VCCO rails and all carrier-side loads. Open: U14 = the VCC_SOM monitor per the carrier schematic; per-rail split (DS987 lists SOM "PL/PS power domain monitor" devices at 0x68/0x70, unused).
- **B2 Clock sweep 100–300 MHz in 25 MHz steps (9 points; user 2026-09-29) on the 300 MHz bitstream, pl_clk0 changed at runtime via PYNQ (`Clocks.fclk0_mhz`), capped at the deployed bitstream's closed clock (on the 250 MHz fallback: 100–250, 7 points); the read-back clock is recorded and used (the PS PLL may not hit every grid point exactly):** latency, power, energy; per-layer and total cycle identity checked at every point (PASS/FAIL, `hw_b2_cycles.csv`); P = P_static + k·f fit with 95 % CIs for both terms (`hw_b2_fit.csv`). Runtime clock switching to be verified at bring-up; fallback one bitstream per clock. Power per clock uses the same INA260 SOM-rail logger (`board/power_log.py`, label "SOM-rail power (INA260)"). The performance bitstream is chosen in Session 1 by `clock_fallback.py` (300 MHz build first, the 250 MHz build if the 300 MHz smoke test fails; 200 MHz only with the explicit `--allow-lower`); the choice is recorded (`hw_clock_choice.json`, state provenance) and every later session uses it.
  - **Cycle identity across clocks** (`hw_b2_cycles.csv`): per layer and total, the cycle counts at every sweep clock must be identical (and equal the model): PASS/FAIL per net.
  - **Power-vs-clock fit** (`hw_b2_fit.csv`): least squares P = P_static + k·f on the per-clock mean SOM-rail power, separately for P_accel, ΔP_accel and P_idle; reported P_static and k with standard errors and 95 % CIs (Student t, n − 2 degrees of freedom), R², n (number of clocks). `exp_b2_clock.py --fit-only` recomputes the fit from existing per-clock files.
- **B3 End-to-end breakdown:** host-side phases per image with `time.perf_counter_ns` (≥ 1000 kept images per condition, 50 warm-up discarded per condition and 5 at the start of every block; median with the distribution-free 95 % CI, p5, p95, p99). The conditions — safe host path, fast host path (only after the bring-up check), and the CPU INT8 reference (1 thread, same pinned core; `hw_b3_breakdown_cpu.csv`) — run **interleaved in one process** in randomized blocks (every round runs each condition once in a seeded random order; seed recorded): input write, status clear (soft_reset of the previous job's sticky done), start→done (= CTRL.start write + STATUS poll, also reported separately), LOGIT read, PS dequant, end-to-end (sum), counter read (measurement overhead, not in end-to-end), PL compute (TOTAL_CYC / f_meas). Measured for **both host paths**: safe (per-word MMIO, `hw_b3_breakdown.csv`) and fast (PL windows mapped once, the input image as one vectorized numpy copy into ACT0, the 16 LOGIT words as one vectorized read, tight STATUS poll; `hw_b3_breakdown_fast.csv`). The fast path is used on the board only after its bring-up check (Session 1 `s1.fast`: whole ACT0 window written fast and read back word by word, CSR block reads == per-word reads, both nets bit/cycle-exact); otherwise it is not run and the safe path is the result. The paper table reports safe vs fast per phase and the end-to-end speedup (safe median / fast median, computed). A laptop MockMMIO comparison of the two host code paths (`board/exp_host_overhead.py`, `results/dryrun/host_overhead_mock.csv`, "host overhead, laptop mock (MockMMIO), not KV260") is a dry-run aid only and never a B3 result.

## C — Optional / robustness
- **C3 Soak** (`exp_soak.py`, step `s3.soak`): 30 min (`--quick` 5 min) of back-to-back inference at the performance clock (or the recorded 250 MHz fallback), LeNet-5 and CIFAR-10 alternating every 60 s; every job checked bit-exact (logits) and cycle-exact (TOTAL_CYC / LAYER_CYC vs the model); counts of logit mismatches, cycle mismatches, job errors, timeouts, STATUS errors and PS_BUSY_VIOLATION flags (all expected 0), per-minute throughput and AMS die temperature (`board_env.read_die_temp`) → `hw_soak.csv`, `hw_soak_minutes.csv`; aborts after > 100 errors; not resumable (one uninterrupted run).
- **C1** (optional) 16x16 post-implementation only.
- **C2** (optional) normalized comparison with prior work.

## Measurement rigor (board sessions, `board/run_sessions.py`)
- **Environment pre-flight** (every invocation, recorded in the state provenance and, via `$GOS_RUN_ENV`, in every row: `session_index, paper_grade, env_step, cpu_governor, cpu_freq_khz, cpu_affinity, die_temp_start_c, env_note`): no package manager running (apt, apt-get, dpkg, unattended-upgrades, packagekitd, apt.systemd.daily — offenders listed); every cpufreq policy set to governor `performance` with scaling_min = scaling_max = one fixed frequency (default the highest available) and `scaling_cur_freq` read back equal to it (restored on exit); every step process pinned (sched_setaffinity = `taskset`) to the measurement core (default 3; the orchestrator runs on the other cores) and read back; die temperature from the Zynq MPSoC AMS (iio, else hwmon) at the start and end of every step (non-fatal, "unavailable" recorded). Governor / pinning / package-manager failures abort a paper-grade run; `--allow-non-paper-grade` proceeds but marks every row `paper_grade=False`, like `--allow-dirty` and every dry run. The paper pipeline rejects board rows with `paper_grade != True`.
- **Measured PL clock = cross-check only** (`board/exp_fclk_cal.py`, steps `s1.fcal`, `s2.fcal`, `s3.fcal`; DECISIONS D20): **every µs value** (A2 PL latency, B3 pl_compute, B1/B2 t_PL and E_comp) uses the pl_clk0 **PLL read-back** frequency (`f_used_source` = f_readback), which the driver sets to the bitstream's closed clock and verifies on every overlay load (D19). f_meas checks that the PL really runs at that frequency: per job, the start→done time is measured with CLOCK_MONOTONIC_RAW (not slewed by NTP) and TOTAL_CYC read; LeNet-5 and CIFAR-10 jobs (deterministic ~16k / ~104k cycles) run back to back in randomized ABAB blocks (≥ 8 s in total); between CTRL.start and the first STATUS poll the driver waits a seeded random time in [0, 2 poll periods) so that the done-detection latency is uniform over the poll grid; f_meas = (C_CIFAR − C_LeNet) / (min t_CIFAR − min t_LeNet) — the minima remove every additive delay and the common minimum latency cancels. Uncertainty: 95 % t-interval over 8 interleaved folds (fold min/max also recorded); systematic: the timer and pl_clk0 share the PS reference oscillator, so f_meas verifies the PLL configuration / pynq read-back, not the crystal's ppm accuracy; timer granularity ≤ 10 ns. **|f_meas − f_readback| / f_readback > 0.1 % is flagged** (`fcal_flag`, FLAG line in the step log and the session summary). The former median-based estimator is still recorded (`f_median_est_mhz`): it read +1.0 % on the first board run because the cycle counts are deterministic and one poll takes ~3.5 µs, so each net's detection latency is a fixed phase of the poll grid that medians do not cancel; `f_simple` (one job length, −4 %) contains the whole start + detection latency. f_req (requested), f_readback (pynq) and f_meas are recorded.
- **Statistics** (`board/stats.py`): warm-up discarded; ≥ 100 kept repeats per latency condition (`repeats_ok`); median with the distribution-free order-statistic 95 % CI (binomial; achieved coverage reported), p95 as the tail; bootstrap only for ratio estimators. Conditions compared in one run are interleaved in randomized blocks with a recorded seed (B3 safe / fast / CPU; B1 accel / control / CPU phase order).
- **3-session repeatability:** the whole campaign (Sessions 1–3) is run three times on different days with `--session-index 1|2|3` (results of index 1 in `results/`, of 2 and 3 in `results/rep2/`, `results/rep3/`); `board/aggregate_sessions.py` combines the per-session statistics (latency medians, power means over repeats, f_meas, accuracy, cycles) into `results/hw_repeatability.csv`: mean of the per-session values ± between-session SD, range, CV, n; rows from different bitstreams or clocks are never combined. Paper table `tab_repeatability`.
- **Priority** (the time budget defers the tail first): bring-up, f_meas cross-check, A3 (+ A3b), A1, latency (A2 + B3), shapes (A3-general), baselines (CPU, DPU), energy (B1), sweep (B2), soak (C3), A4.
